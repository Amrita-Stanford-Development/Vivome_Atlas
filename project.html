The projection service is not yet deployed. The backend pipeline is real and runs end to end against the trained v3 reference (versions), but this page isn't wired up to it yet. It validates your file locally and reports what it found — it does not return coordinates or labels, because this page producing either on its own would mean inventing them.

Supported label space

A projection is only meaningful onto cell types the atlas actually supports. The service returns no label when a query falls outside this space rather than guessing at it.

Service contract

The backend built in Phase 5 implements this interface.

Schema illustration. Every value below is a placeholder showing the response shape. None of them is a measurement. 
POST /api/project
Content-Type: multipart/form-data

  modality : "rna" | "prot"
  matrix   : CSV, features in rows, cells in columns

200 Response
{
  "atlas_version"        : <string>,
  "n_cells"              : <int>,
  "n_features_matched"   : <int>,
  "n_features_unmatched" : <int>,
  "cells": [
    {
      "cell_id"     : <string>,
      "coordinates" : [<float>, <float>, <float>],
      "label"       : <string>,
      "label_set"   : [<string>, ...],
      "confidence"  : <float 0-1>,
      "abstained"   : false
    },
    {
      "cell_id"       : <string>,
      "coordinates"   : [<float>, <float>, <float>],
      "label"         : null,
      "label_set"     : [],
      "confidence"    : null,
      "abstained"     : true,
      "abstain_reason": "outside supported latent space"
    }
  ]
}

label_set is a conformal prediction set at the stated coverage level, not a single argmax. abstained is true when the query falls outside the region the atlas has evidence for.
