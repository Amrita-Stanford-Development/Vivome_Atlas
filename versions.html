Model card, data availability, and the protocol for releasing a new atlas version.

Current release

Architecture change: complete

The reference moved from CrossModalNet, a single model jointly trained on RNA and proteomics together, to a frozen RNA-only reference with a separately trained query encoder. This was a structural change, not a metric update — the joint model could implicitly see SCoPE2 during training, which is part of why its zero-shot numbers below read higher than the honestly separated architecture's do. Both sets of numbers are real; they answer different questions, and the lower number is the trustworthy one, not a regression. The same argument explains the drop in the pca_centroid_cosine column of the diagnostics table for both cross-modal classes — read the current values there, not here, since this page doesn't duplicate manifest-driven numbers into static text: the old jointly trained model's centroids trivially coincided across modalities, and the new frozen RNA-only reference never saw protein data during training, so its centroids no longer do.

The architecture was decided by a five-seed comparison over the widened 9,002-gene feature space (module-pooling encoder, uniform masking — see the model card above for the settled details), and the reference is now trained with it: reference_model.pt, reference_embedding.npy, and reference_centroids.npy are real, live artifacts. The projection pipeline runs against them end to end; it is not yet deployed behind the projection page, which is a separate, still-open piece of work.

Prior baseline — kept, not erased

Projection service model card

The reference encoder is trained, supervised, on RNA only — 85,233 cells across 22 immune/blood cell classes. It is applied zero-shot to proteomics uploads: no protein labels and no paired RNA-protein cells were used at any point in training. Full detail, sources, and the numbers below: service/model/MODEL_CARD.md.

A previously published RNA→RNA figure of 95.5% / 74.8% is superseded by the 93.2% / 65.7% figures above — the published number's test split included cells the model had trained on.

The restricted 79.8% is exact for SCoPE2 by construction: SCoPE2's protein cells are only ever macrophage or monocyte, so restricting to exactly those two classes matches its true label set on this one dataset. On other data with other cell types present, the same hardcoded restriction is wrong — see failure mode 1. Separately, SCoPE2 unrestricted results vary strongly across retrains: a faithful retrain of the same recipe scored 9.1% balanced accuracy against the 31.1% shipped above. Seed variance measurement is pending (T1 NB1c).

Known failure modes:

  1. Hardcoded two-class label space: a non-myeloid protein upload (T cell, NK cell, B cell, etc.) can only ever be labelled macrophage, monocyte, or abstain — never its true label. A correctness limitation, not only an accuracy one.
  2. Macrophage placement: cross-modal alignment is weak for macrophage specifically (latent centroid cosine 0.19 vs. 0.83 for monocyte; protein-side recall 0.76%), even though the macrophage-vs-monocyte ranking itself is correct (AUC 0.928).
  3. Only 2 of 22 reference classes (macrophage, monocyte) have ever been validated against real protein data.
  4. No donor-level holdout in training — all nine donors contributed about 65% of their own cells to the training set.

Data availability

Release protocol

  1. Freeze inputs: record accession numbers, download dates, and checksums for every dataset.
  2. Train and export, then regenerate the manifest with python3 tools/build_manifest.py.
  3. Bump ATLAS_VERSION in tools/build_manifest.py and commit the regenerated manifest.
  4. Tag the release and archive it for a persistent identifier.
  5. Record label stability against the previous version and add it to this page.

Label stability across versions is not yet measured. It is reported here from the first release that has a predecessor to compare against.
