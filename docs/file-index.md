# File index

One line per tracked file: what it contains. For how the folders fit
together, read [project-structure.md](project-structure.md) first.

`scripts/check_paths.py` fails if a tracked file is missing from this page.
When you add, move or delete a file, update its line in the same commit.

## Repository root

- `README.md` — what the project is, quick start, repository map, test commands
- `CLAUDE.md` — working rules for anyone (human or agent) changing the repo
- `package.json` — marks the JS as ES modules and runs `node --test`; there are no dependencies
- `.gitattributes` — the six Git LFS files: three RNA tables in `web/data/`, three model files in `service/model/`
- `.gitignore` — Python and OS clutter, plus the local-only `data/incoming/` folder

## web/ — the public website (static, no build step)

- `web/README.md` — how to serve the site and what each folder under `web/` holds
- `web/index.html` — landing page: animated intro, nav to every section
- `web/atlas.html` — interactive 3D cell viewer (RNA + protein), with the cross-modal support map and alignment diagnostics
- `web/visual.html` — viewer for the 30 precomputed 3D plots (supervised and semi-supervised)
- `web/project.html` — projection page: the upload contract and the supported label space
- `web/benchmark.html` — standing comparison against established integration methods (rows stay pending until sign-off)
- `web/versions.html` — model card, data availability, prior baseline, release protocol
- `web/miscellaneous.html` — intentionally blank (the former roadmap page); kept on purpose
- `web/css/page.css` — shared styling for every page
- `web/js/manifest.js` — loads, validates and formats the manifest; `isMeasured()` is the one guard on displaying a number
- `web/js/panels.js` — pure builders that turn manifest records into HTML strings for each page's panels
- `web/tests/fixtures.js` — shared manifest fixture for the JS tests, including a `<script>` class name that proves escaping
- `web/tests/manifest.test.js` — tests for `manifest.js`: validation, formatting, the measured/pending guard
- `web/tests/panels.test.js` — tests for `panels.js`: every panel builder, and HTML escaping
- `web/tests/lfs.test.js` — pins the Git LFS pointer check, and asserts the shipped RNA files are still pointers
- `web/data/atlas_manifest.json` — generated by `scripts/build_manifest.py`; the only source of every number the pages show
- `web/data/metadata_RNA_lat128.csv` — RNA cell metadata (85,233 rows): class, lineage, 3-PC coordinates
- `web/data/metadata_PROT_lat128.csv` — protein cell metadata (1,490 SCoPE2 rows): true and predicted class, abstention, 3-PC coordinates
- `web/data/atlas_PROT_lat128.csv` — protein cells with 3-PC coordinates and per-gene values (~45 MB)
- `web/data/atlas_PROT_lat128.parquet` — the same protein table as Parquet
- `web/data/atlas_RNA_lat128.parquet` — RNA cells with 3-PC coordinates and per-gene values (Git LFS, ~1.43 GB)
- `web/data/atlas_RNA_lat128-001-part1.csv` — first half of the RNA table as CSV (Git LFS)
- `web/data/atlas_RNA_lat128-001-part2.csv` — second half of the RNA table as CSV (Git LFS)
- `web/plots/supervised/interactive_latent*_to3d_PCA_mm.html` — 5 standalone Plotly plots, one per latent size (32, 64, 128, 256, 512)
- `web/plots/semi-supervised/PCA3D_semi_r*_p*.html` — 25 standalone Plotly plots: RNA label % (`r`) × protein label % (`p`), each in {5, 10, 25, 50, 75}

## service/ — the projection API (Python, its own dependencies)

- `service/README.md` — what the service does, how each pipeline stage works and why, how to run and test it
- `service/__init__.py` — makes `service` a package (`python3 -m service.app`)
- `service/app.py` — the HTTP app: `POST /api/project`, which runs the pipeline on an uploaded matrix
- `service/config.py` — every model path (each can be overridden with a `VIVOME_*` environment variable) and every tuned constant
- `service/requirements.txt` — the service's Python dependencies: torch, NumPy, SciPy, scikit-learn, POT (optimal transport), faiss-cpu
- `service/pipeline/__init__.py` — package marker
- `service/pipeline/pipeline.py` — orchestrator: runs Stages 1–8 and builds the response
- `service/pipeline/alignment.py` — Stage 1: map the upload onto the 9,002-gene feature space; value-scale and mask conventions
- `service/pipeline/smoothing.py` — Stage 2: fuzzy neighbourhood smoothing of sparse proteomics profiles
- `service/pipeline/encoder.py` — Stage 3: the module-pooling reference encoder, and loading it
- `service/pipeline/assignment.py` — Stage 4: label assignment (nearest centroid, OT or kNN) within the supported classes
- `service/pipeline/calibration.py` — Stage 5: conformal calibration on a random slice of the query
- `service/pipeline/abstention.py` — Stage 6: when to refuse a call
- `service/pipeline/fallback.py` — Stage 7: hierarchical fallback to a lineage when a class call is too uncertain
- `service/pipeline/transfer.py` — Stage 8: transfer continuous cell properties from the reference
- `service/pipeline/reference.py` — loads the reference files in `model/runtime/`, with typed errors when one is missing
- `service/pipeline/coordinates.py` — projects latent vectors onto the 3 principal components the viewer plots
- `service/pipeline/topk.py` — top-k cosine search shared by kNN assignment and the reference search
- `service/pipeline/search.py` — FAISS max-cosine search, checked against the exact NumPy result
- `service/pipeline/gene_ids.py` — resolves gene symbols, Ensembl IDs and UniProt accessions to the feature space
- `service/pipeline/validation.py` — upload validation before Stage 1: matrix orientation and minimum cell count
- `service/examples/README.md` — what the example files are, and why their labels are weak
- `service/examples/pbmc240_zscored_all_genes.csv` — PBMC240 protein matrix (237 cells) in the upload format; can be posted to `/api/project` as-is
- `service/examples/pbmc240_cell_metadata.csv` — weak, marker-derived lineage labels for the PBMC240 cells
- `service/examples/pbmc240_provenance.json` — how the PBMC240 matrix and its labels were derived
- `service/examples/pbmc240_proteins_raw.tsv` — raw DIA-NN protein-group output behind the PBMC240 matrix (audit trail only)
- `service/tests/__init__.py` — package marker
- `service/tests/fixtures.py` — shared synthetic fixtures; uses the real reference files where they are small enough
- `service/tests/fixtures/golden_scope2_50.json` — frozen full response for 50 SCoPE2 cells (golden regression)
- `service/tests/fixtures/golden_pbmc240_50.json` — frozen full response for 50 PBMC240 cells (golden regression)
- `service/tests/test_app.py` — HTTP endpoint: request parsing, error responses, response schema
- `service/tests/test_pipeline.py` — end-to-end wiring on the real production checkpoint and reference
- `service/tests/test_e2e_real_export.py` — regression guard: the real SCoPE2 export still reproduces the notebook's own outputs
- `service/tests/test_golden_fixtures.py` — full responses must match the frozen golden fixtures
- `service/tests/test_config.py` — the supported-class constant must match the classes with real protein coverage
- `service/tests/test_alignment.py` — Stage 1 tests
- `service/tests/test_smoothing.py` — Stage 2 tests
- `service/tests/test_encoder.py` — Stage 3 tests, including the TorchScript-vs-eager equivalence check
- `service/tests/test_assignment.py` — Stage 4 tests
- `service/tests/test_calibration.py` — Stage 5 tests
- `service/tests/test_abstention.py` — Stage 6 tests
- `service/tests/test_fallback.py` — Stage 7 tests
- `service/tests/test_transfer.py` — Stage 8 tests
- `service/tests/test_reference.py` — reference loaders, including the missing-file errors

### service/model/ — the model and its evidence

- `service/model/README.md` — what each model file is, and which folder it belongs in
- `service/model/MODEL_CARD.md` — what the model claims, how well it performs (every number cites its source table), known failure modes
- `service/model/canonical_preprocessing.json` — the preprocessing contract an upload must match (convention, log transform, mask, minimum genes)
- `service/model/runtime/reference_model.pt` — the production v3 encoder checkpoint (Git LFS, ~94 MB)
- `service/model/runtime/reference_embedding.npy` — every RNA reference cell in the 128-d latent space (85,233 × 128)
- `service/model/runtime/reference_centroids.npy` — one latent centroid per class (22 × 128), in `class_idx` order
- `service/model/runtime/reference_metadata.csv` — reference cell id, class index, class name and lineage; its `class_idx` order is authoritative
- `service/model/runtime/reference_properties.npy` — per-cell continuous property scores (85,233 × 8)
- `service/model/runtime/property_names.json` — column names and order for `reference_properties.npy`
- `service/model/runtime/feature_space_genes.csv` — the 9,002-gene input space; its row order is authoritative
- `service/model/runtime/gene_id_map_v1.tsv` — frozen symbol ↔ HGNC ↔ Ensembl ↔ UniProt table for the 9,002 genes
- `service/model/runtime/gene_id_map_v1_provenance.json` — where the gene ID table came from: HGNC source URL, date, sha256s
- `service/model/runtime/provenance.json` — serving constants and headline numbers (gene list hash, abstain threshold, seed statistics)
- `service/model/runtime/decisive_summary.json` — the architecture decision (module pooling, uniform masking) that the encoder loader reads
- `service/model/evidence/feature_space_detail.csv` — for each gene, which of the six proteomics sources detected it
- `service/model/evidence/feature_space_provenance.json` — the union arithmetic behind the 9,002-gene figure
- `service/model/evidence/masking_test_tables/rna_sweep.csv` — architecture comparison: balanced accuracy vs. coverage, per arm and seed
- `service/model/evidence/masking_test_tables/scope2_projection.csv` — architecture comparison on SCoPE2: AUC, balanced accuracy, in-support rate
- `service/model/evidence/v3_tables/app_export_summary.json` — summary of the v3 export: gene hash, class counts, supported classes
- `service/model/evidence/v3_tables/held_out_types.csv` — held-out cell-type detection: scores for unseen vs. seen classes, AUC
- `service/model/evidence/v3_tables/latent_centroid_cosine.csv` — per-class RNA/protein centroid cosine; the source of the manifest's metric
- `service/model/evidence/v3_tables/modality_probe.json` — how separable RNA and protein are in the latent space (balanced accuracy)
- `service/model/evidence/v3_tables/property_validation.csv` — per-property transfer quality (r, R²) and whether it ships
- `service/model/evidence/v3_tables/reference_reliability.csv` — per-class reference reliability: recall, silhouette, hubness
- `service/model/evidence/v3_tables/reference_seeds.csv` — training metrics for each of the 5 reference seeds
- `service/model/evidence/v3_tables/rna_to_rna_real_masks.csv` — RNA→RNA accuracy under real proteomics missingness masks
- `service/model/evidence/v3_tables/scope2_hierarchical_calls.csv` — hierarchical fallback calls on SCoPE2
- `service/model/evidence/v3_tables/support_restricted_assignment.csv` — accuracy with the candidate classes restricted vs. unrestricted
- `service/model/evidence/v3_tables/zero_shot_all_datasets.csv` — zero-shot results on each proteomics dataset
- `service/model/source/VivOME_Prototype_Export.ipynb` — the Colab notebook that trained and exported the v3 reference
- `service/model/source/v3_export_manifest.json` — sha256 manifest of the v3 bundle, verified before promotion
- `service/model/source/pca3_projection.npz` — the 3-component PCA basis over the latent space (components, mean, variance ratio)
- `service/model/source/app_export/README.md` — what the saved export artifacts are, and which tests use them
- `service/model/source/app_export/BUNDLE_MANIFEST.json` — sha256 manifest of the app export bundle
- `service/model/source/app_export/blood_joint_cells_by_proteins_GENELEVEL.tsv` — the raw SCoPE2 protein input the export used (Git LFS, ~82 MB)
- `service/model/source/app_export/prot_embedding_scope2.npy` — the export's own latent embedding of the SCoPE2 cells
- `service/model/source/app_export/atlas_PROT_v3_meta.csv` — the export's per-cell SCoPE2 calls: predicted vs. true class, abstention, PCs
- `service/model/legacy/dev/README.md` — why the development checkpoint is not the production model
- `service/model/legacy/dev/H_seed4.pt` — development placeholder checkpoint, used only by one guard test (Git LFS, ~94 MB)
- `service/model/legacy/v2/README.md` — the previous model (CrossModalNet), kept as a baseline and audit trail
- `service/model/legacy/v2/provenance.json` — CrossModalNet's training config and headline numbers
- `service/model/legacy/v2/shared_genes.csv` — CrossModalNet's 2,903-gene feature space

## benchmark/ — fair comparison harness

- `benchmark/README.md` — what the harness compares, how to run it, where outputs go
- `benchmark/.gitignore` — keeps the 1 GB `results/` cache out of git (some of it takes hours to regenerate)
- `benchmark/load.py` — builds the shared, label-free inputs (RNA reference, SCoPE2) that every arm scores
- `benchmark/evaluate.py` — the one shared evaluation protocol: classifier, regimes, bootstrap CIs
- `benchmark/ours_run.py` — scores the shipped encoder through the shared harness
- `benchmark/scanvi_run.py` — scANVI arm on SCoPE2, explicitly seeded
- `benchmark/scanvi_run_pbmc240.py` — scANVI arm on PBMC240, raw and processed inputs
- `benchmark/maxfuse_run.py` — MaxFuse arm on the full RNA reference
- `benchmark/scglue_run.py` — scGLUE arm on the full RNA reference
- `benchmark/recompute_v2.py` — re-scores every finished arm under the current protocol
- `benchmark/paired_and_pool_first.py` — paired bootstrap of ours vs. scANVI, and the pool-first kNN check
- `benchmark/pbmc240_lineage_prep.py` — builds the PBMC240 inputs in the shared gene space, row order pinned to NB1d
- `benchmark/pbmc240_convention_check.py` — measures how far the service and benchmark preprocessing conventions diverge on PBMC240
- `benchmark/datasets.py` — registry of held-out datasets (Fulcher 2026): input paths and sha256, role, label rules; separate upload and label loaders
- `benchmark/fulcher2026_embed.py` — Fulcher 2026: the checkpoint gate on PBMC240, then all ten models' embeddings through the service's own query path
- `benchmark/scanvi_run_fulcher2026.py` — scANVI arm on Fulcher 2026, two input variants; saves predictions only, never reads labels
- `benchmark/fulcher2026_score.py` — Fulcher 2026 scoring, the only step that reads its labels: both rules, all metrics, the paired bootstrap
