Atlas versions

The model card, its known limits, earlier releases, data availability, and the protocol for releasing a new atlas version.

Current release

Each answer is given at the level the evidence supports: one of the reference's   blood cell types, its group, or its lineage. Where the evidence runs out, it abstains and says why. Each cell also gets a best guess: the encoders' probability joined with the cell's correlation to class means, wherever that correlation carries signal in the upload.   keeps the answers and best guess of   and changes one thing for protein uploads: the correlation is taken with protein class means from sorted immune cells (Rieckmann et al. 2017, PRIDE PXD004352) for the reference classes they cover. Each answer's set holds the best guess, so a protein cell's answer can change with it. An RNA upload is answered exactly as before. Full detail and sources: service/model/MODEL_CARD.md; how it compares with other methods: the benchmark.

The simulated suite is the previous release's, because RNA uploads are answered exactly as before; it had been used before, so it is a safety check, not a fresh test. The development datasets are measured as served. The one tuned setting was chosen on Fulcher 2026, and this release was checked there too.

Known limits

  1. CD8 T cells. The best guess finds   of Fulcher 2026's CD8 T cells, and it finds   of Khoury 2026's (post-hoc; the previous release found  ). Every method tested fails them too. Khoury's CD8 label largely separates naive from memory T cells, the reference files naive CD8 T cells under CD4 T, and Fulcher measures neither CD8A, CD8B nor CD4. The answers stay right because they stop at "T cell" or "lymphoid".
  2. Dendritic cells. The best guess finds   of Fulcher 2026's dendritic cells, up from the previous release's   with the protein class means. Fulcher is development data, and the reference has almost no myeloid dendritic cells.
  3. Macrophages against monocytes. On SCoPE2, restricted to those two classes, the best guess scores   balanced accuracy, below chance ( ): it calls most of the differentiated macrophages monocytes. No method separates them once the matrix is reprocessed (the benchmark).
  4. No external test yet. Fulcher 2026 chose the one tuned setting and checked this release, and Khoury 2026 is post-hoc. An internal test on data we set aside before development, scored once, passed on held-out donors of another blood atlas and on a T-cell line beside HeLa, and failed to tell immune cells from keratinocytes and macrophage-like cell lines from monocyte lines (research/benchmark/heldout/). It could not test CD4 against CD8 T cells; a test on cells sorted by type is written down and waits for data (research/benchmark/protocol-sorted-cd4cd8.md).
  5. Uploads of one sorted cell type. Each gene is scaled within its upload, so a single sorted population, or two close types such as CD4 and CD8 T cells, loses the contrast the model needs: its answers stay confident but are often wrong. Upload mixed cells, never one sorted population alone.
  6. Coverage on protein is approximate. The conformal sets were calibrated on simulated RNA uploads, and on real blood protein they hold the true type less often than they promise, least for CD8 T cells and dendritic cells.
  7. The out-of-distribution filter is weak. It passes most scrambled profiles, and in development tests it refused none of the cells of three cell lines (HEK293T, HCT116 and K562). Most of those cells still abstained as ambiguous, but some got a confident blood-cell answer. A cell unlike any in the reference is not reliably refused.
  8. Human blood and immune cells only. Other tissues and cell lines are outside the reference.

Releases

The reference moved from CrossModalNet, a single model jointly trained on RNA and proteomics together, to a frozen RNA-only reference with a separately trained query encoder. This was a structural change, not a metric update: the joint model could implicitly see SCoPE2 during training, which is part of why its zero-shot numbers below read higher than the honestly separated architecture's do. Both sets of numbers are real; they answer different questions, and the lower number is the trustworthy one, not a regression.

The pca_centroid_cosine column in the diagnostics table has dropped twice, for one reason. The first model was trained on both modalities, so its RNA and protein centroids coincided. The RNA-only references never saw protein, so theirs don't. The column measures the space of v3.1's coordinate encoder, which the later releases share. Read the current values in that table; this page does not copy manifest numbers into static text.

The architecture was decided by a five-seed comparison over the widened  -gene feature space (module-pooling encoder, uniform masking; see the v3 card below for the settled details), and the reference is trained with it: reference_model.pt, reference_embedding.npy, and reference_centroids.npy are real, live artifacts. The projection pipeline runs against them end to end, and it is hosted: the projection page sends an upload to the service on Google Cloud Run, or to a copy you run yourself.

The v3 reference encoder is trained, supervised, on RNA only:   cells across   immune and blood cell classes. It is applied zero-shot to proteomics uploads: no protein labels and no paired RNA-protein cells were used at any point in training. Full detail and sources: service/model/MODEL_CARD.md.

v3's known failure modes:

  1. Two-class label space, now opt-in: when a request restricts labels to the supported classes, a non-myeloid protein upload (T cell, NK cell, B cell, and so on) can only ever be labelled macrophage, monocyte, or abstain, never its true label. Under v3.1 and the releases after it, lymphoid uploads get lymphoid answers (see the model card).
  2. Macrophage and monocyte placement: cross-modal alignment is weak for both SCoPE2 classes (latent centroid cosine   for macrophage,   for monocyte), and across all classes most macrophage protein cells are assigned to monocyte (see the model card).
  3. When v3 was released, only macrophage and monocyte had been checked against real protein data. The releases after it were also scored on Fulcher 2026 and Khoury 2026, which between them have T, NK, B, monocyte and dendritic cells.
  4. No donor-level holdout in training: every donor contributed a large share of its own cells to the training set (see the model card).
  5. High seed-to-seed variance on real cross-modal transfer, not yet explained: retraining the same architecture moves SCoPE2 restricted balanced accuracy by up to   (  across   seeds, shared kNN); the shipped seed happens to be the lowest of them, not a principled choice. A separate development-only check on real PBMC240 data (lineage level) shows the same pattern; see service/model/MODEL_CARD.md for the full detail.

Data availability

Release protocol

  1. Freeze inputs: record accession numbers, download dates, and checksums for every dataset.
  2. Train and export, then regenerate the manifest with python scripts/build_manifest.py.
  3. Bump ATLAS_VERSION in scripts/build_manifest.py and commit the regenerated manifest.
  4. Tag the release and archive it for a persistent identifier.
  5. Record label stability against the previous version and add it to this page.

Label stability between releases is not yet measured. Atlas   answers RNA uploads exactly as  ; on protein uploads its best guess changes, and with it some answers, since each set holds the best guess. The share that changes is not yet computed as a release measure. v3 answers at class level only and the later releases at class, group or lineage level, so comparing them needs a definition first.
