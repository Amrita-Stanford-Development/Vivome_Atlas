Raw or log

A protein table can hold its values raw or as logs, and the service has to know which before it reads a single cell. This topic tells how VivOME finds out, what we did to build and test that, and what we found.

What we did

Words

The words this topic uses, in plain language, from A to Z.

The bank
The real public tables we gathered in Step 1, each with its answer, raw or log, known from its documentation. Every later step was checked on them before the next one began.
Best guess
The cell type the model ranks first for a cell. When a table is read the wrong way, some best guesses change: that is how we measured what a wrong reading costs.
Calibration
Setting the thresholds from tables whose answer is known, so that the promise holds. The calibration tables are used for nothing else.
“Can't tell”
The answer when both readings clear their thresholds: the table could be either. The service then reads it as raw, says so, and the uploader can choose the other reading and send it again.
Centred table
A log table with each protein's average taken away, so its values sit around zero and many are negative. A zero in such a table is a real value.
Constructed log
A log table we make ourselves by taking the log of a raw table. The corpus held no public table labelled log, so the log side was tested this way.
Corpus
The large set of public tables collected in B3 for calibration and the sealed test.
Deposit and accession
A deposit is one study's data in a public store. Its accession is its name there, such as PXD064083.
Design data
The tables the method was built and fitted on: the bank and its variants.
Development data
Tables we may look at, try ideas on and change things for. A test, once scored, becomes development data.
Foreign table
A table that is neither raw nor log, such as z-scores, present-or-absent marks or ranks. Used to check that the detector answers “unlike either” when it should.
Frame
The full list of deposits the corpus could be drawn from, put in a fixed random order before any was opened: deposits.
Gate
A plain rule checked before any statistics, for cases that settle the answer by definition: a real share of negative values means log; whole-number counts mean raw.
Hand audit
A second reading of the documentation behind a sample of tables, to check their labels. In B3 it was done by AI helpers under rules written before they started; Claude read every disagreement again, and a share of the agreements.
Hash split
How each deposit was sent to calibration or to the test: by a fixed scramble of its accession, so nobody chose, and a deposit always lands on the same side.
The k-th smallest
How a threshold is set: sort the calibration tables' scores from low to high and take the one in place k. The number of tables fixes k, so the promise holds.
Log values
Numbers after taking a logarithm. A log turns multiplying into adding: each doubling of a protein adds the same step. Many tools write log values, most often log2.
Lower bound
The smallest miss rate a test result fits, at confidence. If even that is above , the promise is contradicted.
Marks
The two files the test scorer writes: one before it reads any test table, one after it scores them. While either exists, it refuses to run again.
McNemar's test
A test for two methods judged on the same tables. It looks only at the tables where they disagree, and asks whether one wins those more often than chance would.
Median
The middle value: half the values are below it and half above.
Missing value
A protein that was not measured in a cell. Some tools leave the place empty, others write a zero, so what a zero means has to be known too.
The old rule (median-50)
The rule the service used before this work, and still uses on the live site: a table with no negative value whose median is above is read as raw, and any other as log.
PRIDE and MassIVE
The two big public stores of proteomics data our deposits come from.
Probability
Here, the model's estimate, between zero and one, that a table is raw, and that it is log.
The promise (α and δ)
The detector's guarantee: for each kind of table and each size group, the right reading is left out of the answer at most α of the time (here ). δ is how often, at most, the calibration could have been unlucky enough to break that (here ), so we are sure of it.
Provenance label
A table's answer, raw or log, taken from what its software's documentation or its paper says about the file, and fixed before any statistic is computed on it.
Raw (linear) values
The numbers the software writes for how much of each protein it saw, before any log is taken: twice the protein gives about twice the number. Also called linear intensities.
Real log
A log table written by its own software or authors, not made by us. The bank holds a few; the corpus found none.
Rehearsal
A dry run of the test scorer on the calibration tables, to check its code before the one real scoring.
Reserve
The deposits of the frame that B3 never listed. They stay unopened, for a fresh test.
Scale-free measure
A number about a table's shape that does not change when every value is multiplied by the same number, or, for log values, when the same number is added to each. Units cannot fool it.
Sealed test
Tables kept unopened until the method is fixed, then scored once, against expectations written before.
Size group (stratum)
Tables grouped by their number of cells (columns): S1 from to , S2 from to , S3 from to . S3 had too few tables of its own, so its tables join S2's for calibration, as S2+S3.
The sparse-log gap
The detector's weak point: a log table with many values missing can look raw to it. B4 saw it on the bank, and B7 found it in the test.
Spent test
A test that has been scored. Once we have seen its answers it cannot test again, so it becomes development data.
Stage 0
The service's first step with an uploaded table: deciding raw or log, and taking the log when the values are raw. Every later step works on log values.
Threshold
The lowest probability a reading needs to stay in the answer. Each reading in each size group has its own, set by calibration.
Typicality warning
A note in the reply when a table is farther from the tables the detector was built on than any of them is from the rest. Since B4 it no longer changes the answer.
“Unlike either”
The answer when neither reading clears its threshold. The service reads the table as raw, with a warning.
Variant
A changed copy of a table, with a known answer: multiplied, logged, cut to fewer cells, with values taken away. Variants check that the measures behave.
z-score
A value minus its gene's average, divided by its spread. The service z-scores every gene before the model sees it, which removes any log base.
