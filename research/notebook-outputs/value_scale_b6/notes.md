One side runs at a time. Each takes the bank's 37 tables twice:

## Found after the run: bytecode in the staged folder

After the run, the staged folder held three `__pycache__` folders:
`service/`, `service/pipeline/` and `valuescale/`.
- **The cause.** `build_space.py`'s new import check ran without `-B`,
  right after `space_manifest.json` was written. So the folder held files
  its manifest does not list, and the image would have copied them,
  although its Dockerfile sets `PYTHONDONTWRITEBYTECODE`.
- **Why the row passed.** B6_build read the manifest's list, so it
  passed. Its expectation that the staged `valuescale/` holds nothing else
  did not hold for the folder.
- **The fix** (`8449d14`), test first: the check now runs with `-I -B`.
  `scripts/test_deploy_rehearse.py`'s
  `test_the_import_check_leaves_the_staged_folder_as_its_manifest_lists_it`
  failed before the fix and passes after.
- **The rebuild.** The Space was rebuilt from `8449d14`. Its folder and its
  manifest list the same files, with no `__pycache__`.
- **The replies are not affected.** The run's children wrote no bytecode
  (`-B`). Any bytecode they read was compiled from the same sources in the
  same build.
